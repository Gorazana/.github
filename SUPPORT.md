# Gorazana support

## Find the right place

- **Using a package:** consult its README, examples, version-specific documentation, and issue tracker.
- **Bug:** open an issue in the affected package repository with version details, a minimal reproduction, and expected versus actual behavior.
- **Feature proposal:** open an issue explaining the use case, desired public API, and backwards-compatibility implications.
- **Security vulnerability:** follow [SECURITY.md](SECURITY.md), not a public issue.
- **General ecosystem feedback:** use an appropriate discussion or issue tracker when the repository enables it.

Please do not post credentials, tokens, private tenant data, or user information in reports.

## Project status

Some repositories represent roadmap proposals rather than published and supported packages. Check each repository's release tags and documentation before depending on it in production.
